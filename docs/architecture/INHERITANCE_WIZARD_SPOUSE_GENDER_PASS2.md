# F-inheritance-wizard-spouse-gender-pass2

The MA / TN inheritance wizard now captures the surviving spouse's
gender. The Moudawana mapping pass3 had already split husband-* and
wife-* into separate rules; that split was unreachable until the
wizard could distinguish the two. Pass2 closes the gap.

No public calculator activation. The MA / TN result page still shows
"International inheritance review" and no automatic shares.

## Wizard form

`apps/cases/forms.py::InternationalInheritanceWizardForm` gains:

| Field | Type | Validation |
|-------|------|------------|
| `surviving_spouse_gender` | `ChoiceField(choices=husband, wife, widget=RadioSelect, required=False)` | Required only when `spouse_present=True`. Otherwise the field is silently dropped to `""`. |

`to_input_data()` now emits:

```jsonc
"heirs": {
  "spouse": 0|1,
  "surviving_spouse_gender": "husband" | "wife" | null,
  "sons": 0..30,
  "daughters": 0..30,
  "father": 0|1,
  "mother": 0|1,
  "siblings": 0..30
}
```

`null` is emitted whenever `spouse=0`. When `spouse=1` the form
rejects an empty gender with the translated error
*"Please indicate whether the surviving spouse is a husband or a
wife. Moroccan and Tunisian inheritance rules assign different shares
depending on the spouse's gender."*

## Wizard template

`templates/public/_inheritance_wizard_fields.html` renders a
gold-bordered card holding two radio choices ("Husband" / "Wife"). The
block carries `data-spouse-gender-block` and starts hidden when
`spouse_present` is unchecked. A small inline script wired to the
checkbox toggles the `hidden` attribute on `change`. JS-free fallback:
the block stays visible and the server still validates the field.

The radio labels frame the deceased's gender for clarity:

- **Surviving husband (the deceased was a wife)**
- **Surviving wife (the deceased was a husband)**

IT, FR, AR translations are in `locale/{it,fr,ar}/LC_MESSAGES/django.po`
and compiled.

## Next step

Three follow-ups remain before MA inheritance can be activated:

1. **Engine awareness of `surviving_spouse_gender`.** The
   `morocco_inheritance_v1` engine must read
   `heirs.surviving_spouse_gender` and gate `ma-inh-husband-*` /
   `ma-inh-wife-*` rules on it before firing.
2. **hajb-noqsan modelling.** The blocked
   `ma-inh-mother-no-descendants-multi-siblings-blocked` rule still
   needs a Studio-signed numeric share before it can become an
   activatable rule.
3. **Studio review of every rule's `confidence`.** Each rule's
   `extracted_text_snippet` still needs to be cross-checked against
   the full PDF article by a Studio reviewer.

Public activation also still depends on the EU 650/2012
applicable-law decision being wired into the public funnel for
cross-border cases.
