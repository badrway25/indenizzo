# F-tunisia-csp-livre-ix-mapping-draft-pass1

The Tunisia inheritance mapping draft is now committed against the
real, validated CSP Livre IX HTML page. **Every rule is blocked**
because the only article range available on the official page
covers Hajb (éviction successorale) — the very mechanism listed as
`unsupported_mechanisms`. EU 650/2012 is recorded as a non-load-
bearing context source pending an unblock. No public activation, no
DB promotion, no Italia change.

## Next step

Three follow-ups before any TN rule can fire publicly:

1. **Fetch the missing CSP article ranges.** Articles 85–121
   (general succession + Fardh shares) and 144–152 (residual rules)
   live on adjacent jurisitetunisie.com pages not yet in the local
   source tree. Add them to `config/official_source_registry.json`,
   re-run `sync_official_sources` and `validate_official_legal_sources`,
   then extend the extractor to merge multi-page output.
2. **Unblock EU 650/2012.** Either implement an EUR-Lex
   session-aware fetcher (follow the HTTP 202 redirect and poll the
   prepared URL), or manually download
   `https://eur-lex.europa.eu/legal-content/FR/TXT/PDF/?uri=CELEX:32012R0650`
   into `legal_data/sources/eu/official_downloaded/` and re-run
   `sync_official_sources` + `validate_official_legal_sources --commit`.
3. **Engine support for Hajb.** Even with the missing CSP ranges
   fetched, the engine would still need to model Hajb (eviction)
   before any of the 22 rules in this draft could become anything
   other than `blocked`. That is a substantial engine extension
   that should be scoped as its own iter.

The activation guard installed in
`F-morocco-engine-activation-blockers-guard-pass1` already
enforces "no rule with non-empty `activation_blockers` may fire" —
that contract carries forward unchanged for the TN engine when it
eventually wires `tunisia_inheritance_v1` to read this mapping.
